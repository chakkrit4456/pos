แผน: เขียน Prompt สร้างระบบ POS สำเร็จรูป (สำหรับขาย)
Context
ผู้ใช้ต้องการ "prompt" สำหรับสั่ง AI coding agent (เช่น Claude Code) ให้สร้างระบบ POS สำเร็จรูปที่นำไปขายในตลาดได้ ข้อกำหนดหลัก: ลูกค้าปรับแต่งสินค้า/ข้อมูลให้เข้ากับธุรกิจตัวเองได้เต็มที่, เลือกได้ว่าจะรันบนเครื่องตัวเอง (ออฟไลน์) หรือเชื่อมฐานข้อมูลของตัวเอง, ใช้งานได้จริง ไม่มีบั๊ก, UX/UI สวยงาม ไม่มีโค้ดเดิมให้สำรวจ งานนี้คือการเขียนเอกสาร prompt หนึ่งไฟล์

สิ่งที่จะทำเมื่ออนุมัติ
บันทึก prompt ด้านล่างเป็นไฟล์ POS_MASTER_PROMPT.md ในโฟลเดอร์ของเซสชันนี้
ส่งไฟล์ให้ผู้ใช้ และสรุปวิธีใช้ (วางทั้งไฟล์ใน Claude Code ในโฟลเดอร์โปรเจกต์ว่าง แล้วให้ทำทีละ Phase)
ค่าเริ่มต้นที่เลือกเอง (ผู้ใช้แก้ใน prompt ได้): TypeScript ทั้งระบบ, React + Vite + Tailwind + shadcn/ui, Fastify, Drizzle ORM, SQLite เป็นค่าเริ่มต้น + PostgreSQL/MySQL, แพ็กเป็น Electron (Windows) และ Docker

ร่าง Prompt (เนื้อหาไฟล์ที่จะบันทึก)

ทำงานเป็น Phase ตามที่กำหนด แต่ละ Phase ต้องรันได้ ทดสอบผ่าน และ commit ก่อนเริ่ม Phase ถัดไป

# เป้าหมายผลิตภัณฑ์
1. ปรับแต่งได้สูงสุดโดยไม่ต้องแก้โค้ด: เจ้าของร้านกำหนดสินค้า หมวดหมู่ ฟิลด์ข้อมูล ภาษี ใบเสร็จ การชำระเงิน สิทธิ์ผู้ใช้ และหน้าตาร้านเองได้ทั้งหมดผ่านหน้า Settings
2. Deploy ได้ 3 แบบจากโค้ดชุดเดียว
   - Standalone: ติดตั้งเป็นโปรแกรมบน Windows (ไฟล์ .exe installer) ใช้ SQLite ในเครื่อง ทำงานออฟไลน์ 100%
   - LAN multi-terminal: เครื่องหนึ่งเป็น Host อีกเครื่อง/แท็บเล็ตเปิดผ่านเบราว์เซอร์ในวง LAN
   - Bring-your-own-database: เชื่อมฐานข้อมูลของลูกค้า (PostgreSQL, MySQL/MariaDB) หรือรันบนเซิร์ฟเวอร์ด้วย Docker
3. ใช้งานจริงได้ทันที: เร็ว เสถียร ข้อมูลไม่หาย มีสำรอง/กู้คืน
4. UX/UI สวย ทันสมัย ใช้ง่ายสำหรับพนักงานที่ไม่ถนัดคอมพิวเตอร์ รองรับจอสัมผัส

# Tech Stack (บังคับ เว้นแต่มีเหตุผลทางเทคนิคที่ดีกว่า ให้แจ้งก่อนเปลี่ยน)
- Monorepo: pnpm workspaces → `apps/web`, `apps/server`, `apps/desktop`, `packages/shared`, `packages/db`
- ภาษา: TypeScript strict ทั้งระบบ
- Frontend: React 18 + Vite + TailwindCSS + shadcn/ui + TanStack Query + React Hook Form + Zod + i18next (ไทย/อังกฤษ) + lucide-react
- Backend: Node.js 20 LTS + Fastify + Zod validation + JWT (access/refresh) + argon2 สำหรับรหัสผ่าน
- ORM: Drizzle ORM พร้อม schema/migration แยกสำหรับ SQLite, PostgreSQL, MySQL (เขียน repository layer กลางเพื่อให้ business logic ไม่ผูกกับ DB ตัวใด)
- Desktop: Electron + electron-builder (NSIS installer, auto-update ได้ภายหลัง) ฝัง server ไว้ใน process
- เงินทั้งหมดเก็บเป็นจำนวนเต็มหน่วยสตางค์ (integer) ห้ามใช้ float
- Test: Vitest (unit/integration), Playwright (E2E)
- Lint/format: ESLint + Prettier, CI ด้วย GitHub Actions

# First-run Setup Wizard
เมื่อเปิดครั้งแรกต้องมี Wizard แบบทีละขั้น:
1. เลือกภาษา
2. เลือกโหมดฐานข้อมูล: (ก) เก็บในเครื่องนี้ [แนะนำ] (ข) เชื่อมฐานข้อมูลของฉัน → กรอก host/port/user/password/database/SSL, ปุ่ม "ทดสอบการเชื่อมต่อ" ที่แสดงผลชัดเจน, รัน migration อัตโนมัติ (ค) เชื่อมต่อ Host ในวง LAN (ค้นหา Host อัตโนมัติด้วย mDNS หรือกรอก IP)
3. ข้อมูลร้าน: ชื่อ โลโก้ ที่อยู่ เลขผู้เสียภาษี สาขา เบอร์โทร
4. ประเภทธุรกิจ (template): ร้านค้าปลีก/มินิมาร์ท, ร้านอาหาร, คาเฟ่, ร้านเสื้อผ้า, ร้านบริการ, อื่นๆ → ตั้งค่าเริ่มต้นและฟิลด์ที่เหมาะสมให้ (แก้ภายหลังได้)
5. ภาษี: จด VAT หรือไม่, อัตรา (ค่าเริ่มต้น 7%), ราคารวม/ไม่รวมภาษี, ค่าบริการ (service charge)
6. สร้างบัญชีเจ้าของ (Owner) + PIN
7. (ตัวเลือก) นำเข้าสินค้าจาก Excel/CSV หรือใส่ข้อมูลตัวอย่าง
ข้อมูลรหัสผ่านฐานข้อมูลต้องเข้ารหัสก่อนบันทึกในไฟล์ config

# ฟีเจอร์หลัก

## 1. หน้าขาย (POS Screen) — หัวใจของระบบ ต้องเร็วและสวยที่สุด
- Layout: ซ้ายเป็นกริดสินค้า (รูป/สี/ชื่อ/ราคา) + แถบหมวดหมู่ ขวาเป็นตะกร้า
- ค้นหาสินค้าด้วยชื่อ/SKU/บาร์โค้ด, รองรับเครื่องสแกนบาร์โค้ด USB (keyboard wedge) โดยไม่ต้องคลิกช่องค้นหา
- ปรับจำนวน, ส่วนลดรายการ/ทั้งบิล (บาท หรือ %), หมายเหตุรายการ, เลือกตัวเลือก/ท็อปปิ้ง (modifiers), สินค้าชั่งน้ำหนัก/ราคาเปิด
- พักบิล / เรียกบิลคืน, แยกบิล, รวมบิล
- โหมดร้านอาหาร (เปิด/ปิดได้): ผังโต๊ะ, เปิดโต๊ะ, ย้ายโต๊ะ, ส่งออร์เดอร์เข้าครัว (พิมพ์ใบครัว/จอครัว KDS)
- ชำระเงิน: เงินสด (ปุ่มธนบัตรลัด + คำนวณเงินทอน), PromptPay QR ตามมาตรฐาน EMVCo สร้างจากเบอร์/เลขผู้เสียภาษีของร้าน, โอน, บัตร, แบบผสมหลายวิธี, ค้างชำระ/เครดิตลูกค้า — ผู้ใช้เพิ่ม/ซ่อนวิธีชำระเงินเองได้
- เลือกสมาชิก สะสม/ใช้แต้ม
- คืนสินค้า/ยกเลิกบิล ต้องใช้สิทธิ์หรือ PIN ผู้จัดการ และบันทึก audit log
- คีย์ลัดคีย์บอร์ด (F1–F12) ที่กำหนดเองได้, ปุ่มใหญ่พอสำหรับจอสัมผัส

## 2. สินค้า (ปรับแต่งได้ทั้งหมด)
- CRUD สินค้า: ชื่อ, SKU, บาร์โค้ด (หลายรหัสต่อสินค้า, สร้างบาร์โค้ดและพิมพ์สติกเกอร์ได้), รูป, หมวดหมู่หลายระดับ, หน่วยนับ, ราคาขาย, ต้นทุน, ประเภทภาษี
- ตัวแปรสินค้า (Variants) เช่น ไซซ์/สี พร้อมราคาและสต็อกแยก
- Modifiers/ตัวเลือกเสริม (บังคับเลือก/เลือกได้หลายอัน, บวกราคา)
- หลายหน่วยนับและอัตราแปลง (ชิ้น/แพ็ค/ลัง) ราคาต่างกัน
- ระดับราคา (ราคาปลีก/ส่ง/สมาชิก) และราคาตามช่วงเวลา
- สินค้าชุด (Bundle/Set) ที่ตัดสต็อกส่วนประกอบ
- **Custom Fields**: เจ้าของร้านเพิ่มฟิลด์เองได้ (ข้อความ, ตัวเลข, วันที่, dropdown, checkbox, รูป) เลือกได้ว่าจะแสดงในหน้าขาย/ใบเสร็จ/รายงานหรือไม่ ใช้ได้กับ สินค้า ลูกค้า และซัพพลายเออร์
- เปิด/ปิดการขาย, ซ่อนจากหน้าขาย, จัดลำดับด้วย drag & drop, กำหนดสีปุ่ม
- นำเข้า/ส่งออก Excel/CSV พร้อม template, ตรวจสอบข้อมูลและแสดงแถวที่ผิดก่อนบันทึก, แก้ไขหลายรายการพร้อมกัน (bulk edit)

## 3. สต็อก
- เปิด/ปิดการติดตามสต็อกรายสินค้า, อนุญาตขายติดลบหรือไม่
- รับสินค้าเข้า (จากซัพพลายเออร์), ปรับสต็อก, นับสต็อก, โอนระหว่างสาขา
- แจ้งเตือนสินค้าใกล้หมด, Lot/วันหมดอายุ (เปิดใช้ได้)
- ประวัติการเคลื่อนไหวสต็อกทุกรายการ (ledger) ห้ามแก้ยอดตรงโดยไม่มีบันทึก
- ต้นทุนแบบถัวเฉลี่ย (Moving Average)

## 4. ลูกค้า/สมาชิก
- ข้อมูลลูกค้า + custom fields, กลุ่มลูกค้า, ระดับสมาชิก
- แต้มสะสม (กำหนดอัตราได้), ประวัติการซื้อ, ยอดค้างชำระ
- ข้อมูลออกใบกำกับภาษีเต็มรูป (ชื่อ ที่อยู่ เลขผู้เสียภาษี สาขา)

## 5. โปรโมชั่น
- ส่วนลด % / บาท, ซื้อ X แถม Y, ซื้อครบยอดลด, ราคาพิเศษตามช่วงเวลา/วัน, คูปองโค้ด
- กำหนดเงื่อนไข: สินค้า/หมวด/กลุ่มลูกค้า/สาขา/ช่วงวันที่ และลำดับความสำคัญเมื่อหลายโปรซ้อนกัน

## 6. ใบเสร็จและการพิมพ์
- Receipt designer: ลากวาง/เปิดปิดส่วนต่างๆ (โลโก้, หัว, ท้าย, QR, ข้อความโปรโมท, custom fields) พร้อม preview สด
- ขนาด 58mm / 80mm / A4, ใบเสร็จอย่างย่อ และใบกำกับภาษีเต็มรูป (รันเลขที่ตามสาขา/ปี กำหนด prefix ได้)
- พิมพ์ผ่านเครื่องพิมพ์ใบเสร็จ ESC/POS (USB/LAN/Bluetooth) รองรับภาษาไทยถูกต้อง (render เป็นภาพหากเครื่องไม่มีฟอนต์ไทย), สั่งเปิดลิ้นชักเก็บเงิน
- พิมพ์ซ้ำ, ส่งใบเสร็จเป็น PDF, เครื่องพิมพ์หลายตัว (แคชเชียร์/ครัว/บาร์) ตามหมวดสินค้า

## 7. กะการทำงานและเงินสด
- เปิดกะ (เงินทอนเริ่มต้น), นำเงินเข้า/ออก, ปิดกะ นับเงินจริงเทียบยอดระบบ แสดงส่วนต่าง พิมพ์สรุปกะ (X/Z report)

## 8. รายงานและ Dashboard
- Dashboard: ยอดขายวันนี้, จำนวนบิล, ค่าเฉลี่ยต่อบิล, สินค้าขายดี, กราฟรายชั่วโมง/รายวัน
- รายงาน: ยอดขายตามช่วงวัน/สินค้า/หมวด/พนักงาน/วิธีชำระ/สาขา, กำไรขั้นต้น, ภาษีขาย (รายงานภาษีขายรูปแบบที่ใช้ยื่นสรรพากรได้), สต็อกคงเหลือ, การยกเลิก/คืนสินค้า
- กรองข้อมูลได้, ส่งออก Excel/PDF

## 9. ผู้ใช้และสิทธิ์
- บทบาทเริ่มต้น: เจ้าของ, ผู้จัดการ, แคชเชียร์, พนักงานครัว — สร้างบทบาทใหม่และกำหนดสิทธิ์รายข้อได้ (permission matrix)
- เข้าระบบด้วย username/password หรือ PIN สลับพนักงานเร็ว, ล็อกหน้าจออัตโนมัติ
- Audit log ทุกการกระทำสำคัญ (แก้ราคา, ยกเลิกบิล, ลดราคา, แก้สต็อก, เปลี่ยนการตั้งค่า)

## 10. ตั้งค่าและปรับแต่งแบรนด์
- โลโก้ สีหลักของธีม โหมดสว่าง/มืด ภาษา สกุลเงิน รูปแบบวันที่ (พ.ศ./ค.ศ.)
- เปิด/ปิดโมดูล (ร้านอาหาร, สต็อก, สมาชิก, หลายสาขา ฯลฯ) เพื่อให้หน้าจอเรียบง่ายตามธุรกิจ
- หลายสาขา/หลายเครื่อง POS ข้อมูลรวมศูนย์
- จอแสดงผลฝั่งลูกค้า (Customer display) แสดงรายการและ QR ชำระเงิน

## 11. ข้อมูลและความปลอดภัย
- สำรองข้อมูลอัตโนมัติตามเวลา (ไฟล์ในเครื่อง/โฟลเดอร์ที่เลือก) + สำรอง/กู้คืนด้วยมือ
- ทำงานออฟไลน์ได้ในโหมด LAN client: เก็บบิลค้างไว้ในเครื่อง (IndexedDB) แล้ว sync เมื่อเชื่อมต่อได้ โดยไม่เกิดบิลซ้ำ (ใช้ UUID + idempotency key)
- ทุกการบันทึกบิลอยู่ใน transaction เดียว (บิล + รายการ + การชำระ + สต็อก + แต้ม)
- ป้องกัน SQL injection, XSS, rate limit การ login, ไม่ log ข้อมูลอ่อนไหว
- ระบบ License สำหรับการขาย: license key ผูกกับเครื่อง (machine fingerprint), ตรวจสอบออฟไลน์ได้ด้วย signature (Ed25519), ทดลองใช้ 14 วัน, แพ็กเกจกำหนดจำนวนเครื่อง/สาขา — แยกโค้ดส่วนนี้เป็นโมดูลเพื่อเปลี่ยนวิธีได้

# แนวทาง UX/UI (บังคับ)
- สไตล์: สะอาด ทันสมัย มินิมอล แบบ SaaS ชั้นนำ ใช้ design tokens (สี, spacing, radius, font) ที่เดียว ปรับสีหลักตามแบรนด์ร้านได้
- ฟอนต์: "IBM Plex Sans Thai" หรือ "Noto Sans Thai" ฝังในแอป (ออฟไลน์ได้)
- ตัวเลขเงินใช้ tabular numbers, จัดรูปแบบ ฿1,234.50
- ปุ่มเป้าสัมผัสอย่างน้อย 44px, การกระทำหลักเด่นชัด, การกระทำอันตรายต้องยืนยัน
- ทุกหน้าต้องมี empty state, loading skeleton, error state ที่บอกวิธีแก้เป็นภาษาคน
- Toast แจ้งผล, Undo เมื่อเป็นไปได้, ไม่มี popup ซ้อนหลายชั้น
- Responsive: จอ POS 1024×768 ขึ้นไป, แท็บเล็ตแนวนอน/แนวตั้ง, มือถือสำหรับดูรายงาน
- Accessibility: contrast ผ่าน WCAG AA, ใช้งานด้วยคีย์บอร์ดได้ทั้งหมด
- Command palette (Ctrl+K) ค้นหาเมนู/สินค้า/บิล
- Onboarding tooltip ครั้งแรก และหน้า "ช่วยเหลือ" ในแอป
- เป้าหมายประสิทธิภาพ: เพิ่มสินค้าลงตะกร้า < 100ms, ค้นหาในสินค้า 50,000 รายการ < 200ms, เปิดแอป < 3 วินาที

# ข้อกำหนดด้านคุณภาพ
- Unit test ครอบคลุม logic สำคัญ ≥ 90%: คำนวณราคา ภาษี (รวม/แยก VAT, การปัดเศษ) ส่วนลด โปรโมชั่นซ้อน เงินทอน แต้ม สต็อก
- Integration test ทุก API endpoint และรันชุด test กับ SQLite, PostgreSQL, MySQL (ใช้ Docker ใน CI)
- E2E (Playwright): setup wizard → เพิ่มสินค้า → ขาย → ชำระเงินสด/QR → พิมพ์ → คืนสินค้า → ปิดกะ → ดูรายงาน
- ไม่มี error/warning ใน console, TypeScript ไม่มี `any` ที่ไม่จำเป็น
- ทุก migration ต้อง up ได้โดยไม่ทำลายข้อมูล และมี seed ข้อมูลตัวอย่างตามประเภทธุรกิจ

# ลำดับการทำงาน (Phases)
1. โครงสร้าง monorepo, design system, DB layer หลายฐานข้อมูล, auth, setup wizard
2. สินค้า/หมวดหมู่/variants/modifiers/custom fields/นำเข้า-ส่งออก
3. หน้าขาย + การชำระเงิน + PromptPay + ใบเสร็จ/การพิมพ์ + กะ
4. สต็อก, ลูกค้า/สมาชิก, โปรโมชั่น
5. รายงาน/Dashboard, ผู้ใช้/สิทธิ์/audit log, ตั้งค่าแบรนด์/โมดูล
6. โหมดร้านอาหาร (โต๊ะ/ครัว), หลายสาขา, LAN/offline sync, customer display
7. Electron installer, Docker image, backup/restore, license, เอกสาร
8. Hardening: ทดสอบครบ, แก้บั๊ก, ปรับ performance, ตรวจ UX ทุกหน้า

ในแต่ละ Phase: วางแผนสั้นๆ → เขียนโค้ด → เขียน test → รัน test/lint/typecheck ให้ผ่าน → ทดลองใช้งานจริงผ่านเบราว์เซอร์ → สรุปสิ่งที่ทำและวิธีทดสอบ
